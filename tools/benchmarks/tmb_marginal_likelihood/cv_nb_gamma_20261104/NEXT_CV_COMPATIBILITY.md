# CV priorities after NB2/Gamma qualification

Complete full20, exact-source application and the safe checkpoint first. Do not
replay closed producers. No commit/push or broader fitting admission is granted
by this note. Existing priors, diagnostics, K, uncertainty and private guards
remain mandatory.

1. Audit learned formula preprocessing beyond the currently checked native
   polynomial/spline and top-level saved scale metadata. Nested data-dependent
   calls inside I()/offsets or arbitrary user functions are not universally
   qualified. Verify actual retained prediction metadata with independent
   assessment perturbation tests before claiming coverage, and keep explicit
   unsupported cases guarded. Ordinary arithmetic/products/factors do not by
   themselves establish this learned-preprocessing contract.
2. Define GAM/BAM CV around training-only smooth/basis/dispersion estimation,
   native response distributions and effective parameter counts. Multi-component
   families need explicit scoring targets and component conventions; do not
   coerce them into a GLM adapter or mix incompatible density measures.
3. Define mixed and unmarked targets before adding scoring adapters: observed
   versus new groups, conditional versus marginal response prediction, joint
   visit-history probabilities and latent abundance/occupancy integration.
   Existing native pcount AIC support does not itself qualify held-out scores.
4. Bayesian CV needs separately budgeted training fits, unchanged normalized
   priors/reference transforms and posterior-predictive scores. Current plug-in
   mean/nuisance scores add no uncertainty integration or calibration certificate.
5. Consider exact fold-preparation reuse only after source/row/metric/kernel/bin/
   fixed-reference identity is enforced. Performance qualification requires a
   permitted uncontended window; current concurrent-foreign-R timing is ineligible.

Keep tests tied to distinct contracts/regressions rather than an assertion-count
target. Preserve all scientific gates and failures. Consolidation can remove
duplicate setup or redundant assertions later, with equivalent coverage and an
explicit reviewed ledger change; it must not erase numerical/admission cases.
